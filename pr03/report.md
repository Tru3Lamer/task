## Практическая работа №3. Права доступа Linux и управление пользователями

## 1.Пользователи и группы

## Созданные пользователи и их роли

|Пользователь|Группа|Роль|
|alice|developers|Администратор|
|bob|developers|Разработчик|
|carol|auditors|Аудитор|

alice :x:1001:1001::/home/alice:/bin/bash
alice - имя пользователя
x - пароль (хранение /etc/shadow)
1001 - UID
1001 - GID
:_: - comments
/home/alice - home folder
/bin/bash - command shell

**Что хранится в /etc/shadow?**
Хэши паролей пользователей и параметры их действия
**Почему файл недоступен обычным пользователям?**
Права  rw-r-----  (only root, group shadow)

## ACL
ACL лучше стандартной модели, т.к. даёт возможность давать доступ конкретному пользователю, не меняя его группу (работает и с группами тоже)
## sudo 
**Почему alice использует NOPASSWD,а bob нет?**
Элис является администратором, сделано в угоду быстроты доступа. Боб - разработчик. Ему нет необходимости на полный sudo без пароля из-за соображений безопасности. 
Здесь реализован принцип наименьших привилегий. Каждому пользователю выдаётся тот минимум прав, который ему необходим.
