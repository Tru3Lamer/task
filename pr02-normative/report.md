### 2. Анализ уязвимости
**CVE-идентификатор:** CVE-2021-44228
**CVSS Score:** 10.0 (Критический)
**Затронутый продукт:** Apache Lg4j версии  2.0-beta9 до 2.15.0
## Описание
Log4Shell - уязвимость удалённого выполнения кода (RCE) в библиотеке логирования Log4j для Java. Злоумышленник может подставить вредоносную строку в любое поле, которое логируется (User-Agent, параметры запроса, поля форм).
##Механизм Атаки
1.Злоумышленник отправляет запрос с вредоносной строкой
2.Log4j обрабатывает строку и выполняет JNDI-запрос к указанному серверу.
3.Атакующий сервер возвращает Java-класс с эксплойтом.
4.Уязвимое приложение загружает и выплняет этот код.
5.Злоумышленник получает контроль над сервером.
## Требуется ли аутентификация?
**Нет** Attack Vector = Network, Privileges Required = None.

## 4.Контрольные вопросы
**1.Что такое СМЫЫ и какие оценки считаются критическими?**
CVSS (Common Vulnerability Scoring System) - стандарт оценки критичности уязвимостей. Критическими считаются оценки от 9.0 до 10.0.
**2. Чем отличаются Приказ ФСТЭК №17 и №21?**
№17 - для ГИС, №21 - для ИСПДн.
**3. Что такое "вектор атаки" в описании CVE?**
Это способ доступа злоумышленника к уязвимости: Network -удалённо, Adjacent - локальная сеть , Local - локальный доступ , Physical - физический доступ.
**4. Почему уязвимость с CVSS 10.0 не всегда срочная для организации?**
Потому что если в организации не используется затронутое программное обеспечение, то риск нулевой, независимо от оценки CVSS.
**5. Какая группа мер ФСТЭК отвечает за обновление ПО?*
Група **ОПС** (Обеспечение безопасности программ) - пункт о своевременном обновлении ПО и устранении уязвимостей.
