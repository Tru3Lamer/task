*п.28: Какие типы записей вы видите в audit.log? Что означает type=SYSCALL?*
SYSCALL-системный вызов
PATH-путь к файлу
PROCTITLE-командная строка процесса
USER_LOGIN-вход в систему
CWD-текущая директория
SYSCALL означает, что запись создана при выполнении системного вызова ядра - основное событие аудит, содержит auid, uid, comm, exe и код возврата.
*п.30: Что означают колонки в выводе aureport?*
'#'- номер записи в отчёте
count-количество событий данного типа
time-время последнего события
file/key-затронутый файл или ключ правила
*п.37: Что означают поля auid, uid, euid, comm, exe?*
auid-исходный айди пользователя, который вошел в систему.
uid-айди пользователя в момент выполнения системного вызова
euid-эффективный айди, используемый для проверки прав доступа
com-имя команды
exe-полный путь к испольняемому файлу
*п.62: как auditd отличает чтение файла от его изменения?*
По полю syscall и флагам в а0 (первй аргумент в syscall open/openat)
Чтение: syscall=open + flags O_RDONLY в выводе flags=00
Изменение: syscall=open + флаги 'O_WRONLY' или 'O_RDWR' в выводе flags=02  или O_RDWR
Также аудит изменения показывает syscall=rename или syscall=write ,если файл был перезаписан.

## 5. Контрольные вопросы

**65. Чем принципиально отличается auditd от journald? Почему нельзя обойтись только journald?**

auditd работает на уровне ядра и перехватывает системные вызовы (syscalls), а journald — на уровне пользовательского пространства и логирует только то, что отправляют приложения через syslog или systemd. Нельзя обойтись только journald, потому что:
- Приложение может не писать лог о своих действиях (или писать не все), а auditd зафиксирует syscall в любом случае.
- auditd фиксирует даже неудачные попытки доступа (отказ в чтении файла) — journald этого не сделает, если программа не напишет об этом сама.
- auditd сохраняет auid (неизменный ID сеанса) при sudo/su, journald при sudo теряет исходного пользователя.
- auditd может следить за любым файлом или директорией, journald — только за сервисами.

**66. Что такое auid и почему оно важнее uid при расследовании инцидентов с sudo?**

auid (Audit User ID) — это идентификатор, который присваивается при входе в систему и не меняется до выхода. При выполнении sudo uid становится 0 (root), а auid остаётся исходным (например, 1000 для alice). При расследовании это критически важно: без auid вы увидите только "root сделал что-то", а с auid — "alice через sudo сделала что-то".

**67. Что означает флаг -k в правиле auditd? Для чего он используется?**

`-k` задаёт ключ (фильтр) для события. При поиске можно использовать `ausearch -k ключ` чтобы найти все события с этим ключом. Используется для группировки связанных правил: например, все файлы аутентификации помечаются ключом `auth-files`, а все файлы привилегий — `priv-files`.

**68. Чем -w (watch) отличается от -a always,exit в правилах auditd? Когда использовать каждый?**

`-w` (watch) — это упрощённое правило для слежения за конкретным файлом или директорией. Автоматически отслеживает основные операции (read, write, attribute change). Используется когда нужно просто мониторить доступ к файлу.

`-a always,exit` — низкоуровневое правило добавляющее фильтр на конкретный системный вызов (open, unlink, execve, etc.). Используется когда нужны точные условия: например, "только неудачные попытки открытия" (`-F success=0`) или "только для определённой архитектуры" (`-F arch=b64`).

**69. Злоумышленник удалил файл /var/log/audit/audit.log. Как это помогает ему скрыть следы и как от этого защититься?**

Удаление audit.log уничтожает все записи аудита, и администратор не сможет расследовать инцидент. Защита:
1. Настроить отправку audit.log на удалённый syslog-сервер (режим `network` в auditd.conf).
2. Установить неизменяемые атрибуты на файл: `sudo chattr +a /var/log/audit/audit.log` (только добавление) и `+i` (запрет удаления/изменения).
3. Настроить отдельное правило аудита на удаление самого файла audit.log: `-w /var/log/audit/audit.log -p wa -k audit-log-delete`.
4. Использовать `auditd.conf` с параметром `flush = sync` для немедленной записи на диск.

**70. Что нужно сделать чтобы правила auditd сохранились после перезагрузки?**

1. Поместить правила в файл `/etc/audit/rules.d/имя.rules` (например, `security-course.rules`).
2. В начале файла указать `-D` для очистки старых правил при загрузке.
3. Выполнить `sudo augenrules --load` для проверки.
4. Убедиться что сервис auditd включён в автозагрузку: `sudo systemctl enable auditd`.
При загрузке системы `augenrules` автоматически соберёт все `.rules` файлы из директории и применит их.
