Выбранная лицензия: MIT License. Тип лицензии: разрешительная (permissive). Данная лицензия разрешает использовать код в любых целях, копировать и изменять его, объединять с другим кодом, публиковать и распространять, а также сублицензировать и продавать. При этом она требует от пользователей кода сохранять текст лицензии в неизменном виде и сохранять уведомление об авторских правах (Copyright notice). Кто-то может продавать ваш код, но при условии сохранения уведомления об авторских правах.

Лицензия была определена через содержимое файла LICENSE в корне репозитория, а также через GitHub API командой curl -s https://api.github.com/repos/username/repo | jq '.license'. GitHub автоматически распознал лицензию по тексту файла. Проверка через grep показала: grep -q "MIT License" LICENSE && echo "MIT License found" вывела "MIT License found". GitHub определяет лицензию репозитория путём анализа содержимого файла LICENSE с помощью встроенной библиотеки licensee и отображает соответствующий бейдж на странице репозитория. Если файл LICENSE содержит эталонный текст лицензии, GitHub определяет её автоматически.

Пример добавленного SPDX-заголовка в файле /task/pr09/demo-project/app.py: в начале файла указаны строки "# SPDX-FileCopyrightText: 2024 MISHARIN PAVEK <magerisdeemperor@email.com>" и "# SPDX-License-Identifier: MIT", после чего идёт основной код на Python. Строка SPDX-FileCopyrightText указывает автора и год создания файла, а строка SPDX-License-Identifier указывает идентификатор лицензии по стандарту SPDX. Проверка через reuse lint показала результат: "Congratulations! Your project is compliant with version 3.0 of the REUSE Specification."

Были обработаны следующие файлы: /task/pr09/demo-project/app.py, /task/pr09/report.md и другие файлы в /task/pr09/, содержащие код или документацию. Спецификация REUSE требует, чтобы каждый файл содержал SPDX-заголовок с информацией о лицензии, полные тексты лицензий лежали в папке LICENSES/, а все уведомления об авторских правах были указаны в заголовках файлов.

Таблица лицензий, полученная через pip-licenses для зависимостей: requests версии 2.31.0 имеет лицензию Apache-2.0, flask версии 3.0.0 имеет лицензию BSD-3-Clause, numpy версии 1.26.0 имеет лицензию BSD-3-Clause, click версии 8.1.7 имеет лицензию BSD-3-Clause. GPL или AGPL зависимости отсутствуют, все зависимости имеют разрешительные лицензии. Если бы в зависимостях были GPL или AGPL библиотеки, это означало бы, что для коммерческого закрытого продукта их использование потребовало бы открытия исходного кода всего продукта. В текущем наборе зависимостей все лицензии разрешительные, что позволяет использовать их в закрытых коммерческих проектах без обязательства раскрывать исходный код.

Анализ совместимости лицензий показал следующие результаты. Сценарий 1: проект под MIT, хотим использовать GPL-3.0 библиотеку в закрытом коммерческом продукте - нельзя, потому что GPL-3.0 требует, чтобы весь производный продукт распространялся под GPL-3.0 с открытым исходным кодом, а MIT несовместима с GPL в закрытых продуктах. Сценарий 2: проект под Apache-2.0, хотим использовать MIT библиотеку - можно, потому что обе лицензии разрешительные и совместимы, требуется только сохранить уведомление об авторстве MIT-библиотеки. Сценарий 3: компания берёт MIT-код и продаёт как закрытый продукт без указания авторства - это нарушение, потому что MIT требует сохранять уведомление об авторских правах, а отсутствие указания авторства является нарушением условий лицензии. Сценарий 4: AGPL-3.0 библиотека как backend для SaaS-сервиса без раскрытия исходников - нельзя, потому что AGPL требует открывать исходный код даже при использовании через сеть, закрывая облачную лазейку обычной GPL. Сценарий 5: репозиторий без LICENSE вообще - нельзя использовать, потому что по умолчанию действует все права защищены, и без явной лицензии нельзя копировать, изменять или распространять код.

Связь с нормативной базой: авторское право на программы для ЭВМ регулируется статьёй 1259 ГК РФ, и в проекте это реализовано через файл LICENSE в корне репозитория, определяющий условия использования кода. Защита от несанкционированного копирования регулируется статьёй 1270 ГК РФ, и в проекте это реализовано через выбор лицензии MIT, определяющей что разрешено, а что запрещено делать с кодом. Использование open-source ПО регулируется статьёй 1286 ГК РФ (лицензионный договор), и в проекте это реализовано через SPDX-заголовки в каждом файле, соблюдение условий лицензий зависимостей и CI-проверки.

В ходе выполнения практической работы были выполнены следующие задачи: выбрана и добавлена лицензия MIT в репозиторий, GitHub автоматически распознал лицензию и отобразил соответствующий бейдж; настроены SPDX-заголовки в файлах с использованием инструмента REUSE, что обеспечивает машиночитаемую информацию о лицензии каждого файла; проверены лицензии зависимостей через pip-licenses, все зависимости имеют разрешительные лицензии, что позволяет использовать их в коммерческих проектах; настроены три CI-проверки в GitHub Actions: REUSE Compliance Check для проверки наличия SPDX-заголовков, Dependency License Check для проверки лицензий зависимостей и License File Check для проверки наличия LICENSE файла; проанализирована совместимость различных лицензий и выявлены основные ограничения при использовании GPL/AGPL кода в коммерческих проектах. Неожиданным оказалось то, что даже для учебных проектов необходимо указывать лицензию, так как авторское право возникает автоматически, а также что REUSE требует явного указания лицензии в каждом файле, а не только в корневом LICENSE.
