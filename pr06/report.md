# ПР №6. Анализ сетевого трафика: tcpdump и Wireshark

## 1. Разбор строки tcpdump
Строка: `13:37:52.528050 IP 127.0.0.1.43354 > 127.0.0.1.8080: Flags [P.], seq 1:192, ack 1, win 512, length 191: HTTP: POST /login HTTP/1.1`

| Поле | Значение | Что означает |
|------|----------|--------------|
| 13:37:52.528050 | 13:37:52.528050 | Время захвата пакета |
| IP | Internet Protocol | Протокол сетевого уровня |
| 127.0.0.1.43354 | 127.0.0.1 порт 43354 | IP-адрес и порт источника |
| 127.0.0.1.8080 | 127.0.0.1 порт 8080 | IP-адрес и порт назначения |
| Flags [P.] | PUSH + ACK | Флаги TCP: PUSH (немедленная отправка) + ACK (подтверждение) |
| length 191 | 191 байт | Длина данных в пакете |

## 2. Перехваченные данные HTTP
![Пароль в открытом виде](screens/http-password.png)

Что видно в трафике: `username=admin&password=supersecret123` — логин и пароль передаются открытым текстом.

Кто в реальной сети может так же прочитать этот трафик: любой, кто находится в том же сегменте сети и использует сниффер (tcpdump, Wireshark) или злоумышленник, который выполнил ARP-spoofing.

## 4. HTTP vs HTTPS — сравнение
| Что наблюдаем | HTTP | HTTPS |
|---------------|------|-------|
| IP-адреса | Видны | Видны |
| Заголовки | Видны | Зашифрованы |
| Тело запроса | Видно | Зашифровано |
| Логин/пароль | Видны | Не видны |
| Имя домена | Видно в Host | Видно в SNI |

## 5. DNS и приватность
Какие домены видны в DNS даже при HTTPS: github.com, example.com, google.com

Что это означает для приватности: DNS-запросы не шифруются, поэтому даже при использовании HTTPS видно, какие сайты посещает пользователь.

## 6. Base64
Декодированная строка: `dmFzeWE6TXlQYXNzd29yZDIwMjQ=` → `vasya:MyPassword2024`

Почему Base64 не является шифрованием: Base64 — это просто кодирование (преобразование бинарных данных в текст). Оно не использует ключ и не обеспечивает конфиденциальность. Любой может декодировать строку обратно.

## 7. tshark vs tcpdump
| Инструмент | Когда использовать |
|------------|-------------------|
| tcpdump | Быстрый захват трафика в консоли, без GUI, для сбора pcap-файлов |
| tshark | Консольный анализ pcap-файлов, автоматизация, фильтрация по протоколам |
| Wireshark | Детальный анализ с GUI, визуализация, Follow TCP Stream |

## 8. Каналы утечки через сеть
Какие меры защиты закрывают сетевой канал утечки: 
- Использование HTTPS/TLS для шифрования трафика
- VPN для шифрования всего трафика
- DNSSEC, DoH/DoT для защиты DNS
- Корпоративные прокси с фильтрацией

## Выводы
В ходе работы был проанализирован сетевой трафик с помощью tcpdump и tshark. Продемонстрировано, что HTTP передаёт данные (логин, пароль) в открытом виде, что позволяет злоумышленнику перехватить их с помощью сниффера. HTTPS шифрует все данные, кроме IP-адресов и имён доменов (через DNS и SNI). Base64 не является шифрованием и не обеспечивает безопасность.
